# 用户聊天功能 · 合规评估

> 评估日期：2026-09-29
> 触发原因：考虑给看板增加「用户聊天的面板」
> **结论：暂不做。** 在当前「个人主体 ICP 备案」下，用户间聊天与公开评论都不合规。
> 本文保留评估过程与法规依据，将来主体性质变化（换成企业备案）时可据此重新决策。

---

## 一、结论速览

「用户聊天」不是一个功能，而是一类功能的统称。四种形态的合规判定差别极大：

| 形态 | 法律定性 | 判定 | 核心障碍 |
|---|---|---|---|
| 用户之间**私聊 / 群聊** | 即时通讯服务 | ❌ 不合规 | 强制真实身份认证（手机号/身份证），个人备案主体不适用 |
| **公开评论区 / 留言板** | 跟帖评论服务 | ❌ 不合规 | 实名 + 审核编辑队伍 + 分级黑名单 + 举报申诉制度 |
| **用户 ↔ AI 对话** | 生成式人工智能服务 | ❌ 面向公众办不了 | 需大模型服务登记，**个人不能作为申报主体** |
| **用户 → 站长单向留言**（不公开、不互通） | 客服 / 意见反馈 | ✅ 风险最低 | 不构成用户间信息发布，也不构成即时通讯 |

一句话概括：**只要内容是"用户写给其他用户看"，就跨过了监管红线；只要内容是"用户写给站点运营者看"，就还在常规反馈的范畴内。**

## 二、法规依据

### 2.1 信息发布 / 即时通讯 → 强制真实身份认证

《互联网用户账号信息管理规定》（国家互联网信息办公室令第 10 号，2022 年 8 月 1 日施行）**第九条**：

> 互联网信息服务提供者为互联网用户提供**信息发布、即时通讯等服务**的，应当对申请注册相关账号信息的用户进行基于**移动电话号码、身份证件号码或者统一社会信用代码**等方式的真实身份信息认证。用户不提供真实身份信息，或者冒用组织机构、他人身份信息进行虚假注册的，**不得为其提供相关服务**。

关键点：认证方式被明确限定为**手机号 / 身份证号 / 统一社会信用代码**。本项目当前采用「邮箱 + 密码」注册 —— **邮箱不属于任何一种法定认证方式**，因此不具备提供该类服务的前提。

同规定其他相关条款：

- **第十二条**：应当在用户账号信息页面展示合理范围内的 **IP 地址归属地**信息。
- **第十四条**：应当履行账号信息管理主体责任，**配备与服务规模相适应的专业人员和技术能力**。
- **第二十二条**：违反本规定的，由省级以上网信部门给予警告、通报批评、责令限期改正，**可处一万元以上十万元以下罚款**；构成违反治安管理行为的移交公安机关，构成犯罪的移交司法机关。

### 2.2 评论 / 留言 → 跟帖评论服务，义务更重

《互联网跟帖评论服务管理规定》（2022 年修订，2022 年 12 月 15 日施行）**第四条**要求跟帖评论服务提供者履行：

1. 按「后台实名、前台自愿」原则，对注册用户进行基于**移动电话号码、身份证件号码或者统一社会信用代码**的真实身份信息认证，**不得向未认证真实身份信息的用户提供跟帖评论服务**；
2. 建立健全用户个人信息保护制度；
3. 对新闻信息提供跟帖评论服务的，建立**先审后发**制度；
4. 建立健全跟帖评论**审核管理、实时巡查、应急处置、举报受理**等信息安全管理制度，及时发现处置违法和不良信息并向网信部门报告；
5. 创新管理方式、提升违法和不良信息处置能力；
6. **配备与服务规模相适应的审核编辑队伍**，加强审核培训；
7. 配合网信部门依法开展监督检查。

该规定对「跟帖评论服务」的定义很宽：以**评论、回复、留言、弹幕、点赞**等方式，为用户提供发表文字、符号、表情、图片、音视频等信息的服务。

> 注意「留言」也在列举范围内 —— 所以**公开的留言板同样被覆盖**，不能靠改个名字绕开。

第五条还要求建立健全**用户分级管理制度**与**黑名单制度**（严重失信用户列入黑名单、禁止重新注册）；另需建立健全**投诉举报与申诉制度**，设置便捷入口。

### 2.3 生成式 AI → 面向公众需登记，个人主体无法申报

若聊天对象是 AI（如「AI 骑行助手」），则落入《生成式人工智能服务管理暂行办法》的管辖：

- 调用**已备案大模型的 API** 做应用封装并面向公众提供服务，仍须由**属地省级网信办**办理**大模型服务登记** —— 上游模型的备案号**不能替代**应用方自身的登记义务。
- **申报主体必须是在中国境内依法设立的法人企业**；自然人、个体工商户均无法提交。这条对本项目是决定性的。
- 2026 年监管明显收紧：中央网信办「清朗·整治 AI 应用乱象」专项行动把「未按规定履行大模型备案登记义务」列为头号整治问题，第一阶段累计处置违规网站、应用程序、智能体等 AI 产品 1.4 万余款。
- 调用**境外未备案模型**（如 OpenAI、Anthropic）向境内公众提供服务，属于监管审查中的高危红线。

> 例外：仅**企业内网 / 纯私人自用、不向社会公众提供**的场景，不强制办理上线备案。若将来要把 AI 助手做成「只有站长账号可用」的工具，性质接近自用，风险显著低得多 —— 但一旦对外开放注册用户使用，就回到「面向公众」，需重新评估。

### 2.4 个人主体备案的额外限制（本项目最直接的约束）

本项目为**个人主体** ICP 备案，这一点比上面几条都更现实：

- 个人备案对应的是**非经营性互联网信息服务**，网站内容应是静态信息展示（个人博客、作品集等）。
- 论坛 / 社区 / BBS / 留言板这类 **UGC 交互功能**在多地通信管理局属明确受限范围；审核时对相关关键词可能直接驳回。
- **广东省属审核严格地区。** 地域差异只是审核阶段的松紧，不代表事后合规 —— 域名解析与服务器 IP 都在联网监控之下，常态化巡查会介入。
- 已有的个人备案站若被查出提供 UGC 交互功能，**接入商可取消备案**。

**风险排序（按对本项目的实际杀伤力）：**

1. **备案被注销** —— 最严重。备案号失效后域名在国内无法使用，网站直接关停，现有的 HTTPS 证书、域名解析、公安联网备案都要重来。
2. **行政处罚** —— 警告、通报批评、责令改正，可处 1 万～10 万元罚款。
3. **内容责任落在个人身上** —— 一旦平台出现违法信息而未尽管理义务，承担责任的是备案主体（个人），而非「平台」这个抽象概念。
4. **备案信息变更义务** —— 从「个人记录工具」变成「UGC 交互平台」是**性质变化**，不只是多一个页面。

## 三、为什么这不是「加一个页面」的量级

引入用户间内容后，站点的身份从**信息展示**变为**信息发布平台的提供者**，随之而来的是：

- 实名认证体系（手机号短信验证 → 需要短信服务、成本与资质）
- 内容审核能力（先审后发 / 实时巡查 / 关键词库）
- 分级管理与黑名单
- 投诉举报与申诉入口
- IP 归属地展示
- 日志留存（《网络安全法》要求不少于 6 个月）
- 未成年人保护相关义务

对个人站长而言，这不是「多做几个功能」，而是**承担一份持续的经营性责任**。

## 四、可选替代方案（已评估）

| 方案 | 合规性 | 说明 |
|---|---|---|
| **骑友交流群外链**（微信群 / QQ 群二维码） | ✅ 完全合规 | 内容与审核责任都在第三方平台，站点只放一个入口。工作量最小、零风险。 |
| **站内「给站长留言」**（单向、仅站长可见） | ✅ 风险最低 | 不构成用户间信息发布，也不构成即时通讯。需要配套：平台公约、隐私说明、举报入口。 |
| **用户间聊天 / 公开评论** | ❌ 不合规 | 需先补齐第二节列出的全部义务，且个人主体备案仍有被注销的风险。 |
| **AI 骑行助手（仅站长自用）** | ⚠️ 需谨慎界定 | 严格限定为不对外开放的自用工具时风险低；一旦开放给注册用户即回到「面向公众」。 |

## 五、若将来要做：合规改造清单

留存备查。前提是**备案主体已换成企业 / 个体工商户不适用于大模型登记，须为企业法人**。

**通用前置**

- [ ] 备案主体变更为企业，并确认经营范围涵盖互联网信息服务
- [ ] 评估是否需要 ICP 经营许可证（经营性互联网信息服务）
- [ ] 制定并公开《用户账号管理规则》《平台公约》《隐私政策》《用户服务协议》
- [ ] 在显著位置设置投诉举报与申诉入口，明确处理流程与反馈时限

**内容类功能（评论 / 留言 / 聊天）**

- [ ] 接入手机号短信验证，实现「后台实名、前台自愿」的真实身份认证
- [ ] 建立内容审核机制（先审后发或实时巡查 + 关键词库）
- [ ] 建立用户分级管理制度与黑名单（含禁止重新注册）
- [ ] 展示用户账号 IP 归属地
- [ ] 日志留存不少于 6 个月
- [ ] 配置与服务规模相适应的审核人员

**AI 类功能**

- [ ] 确认所调用大模型已完成国家网信办备案，留存备案编号与公示截图
- [ ] 向属地省级网信办提交**大模型服务登记**申请（材料：主体资质、登记申请表、与模型服务商的服务协议、算法与内容安全机制说明等）
- [ ] 评估是否需同步办理**生成合成类算法备案**
- [ ] 若对模型输出做实质性二次改造（内容过滤、重组、审核等），可能被认定为「实质性修改」而需升级为完整备案
- [ ] 服务上线后公示备案 / 登记编号及网信办公示链接

## 六、决策记录

| 日期 | 决策 | 理由 |
|---|---|---|
| 2026-09-29 | **暂不做用户聊天功能**，仅保留本评估 | 站点为个人主体备案（广东省，审核严格地区）。用户间聊天与公开评论均属不合规形态；改造为合规形态需要企业主体、短信实名、审核队伍等一整套能力，与当前定位不匹配。风险最重的后果是备案被注销（网站关停）。 |

**重新评估的触发条件**

- 备案主体变更为企业法人，或
- 产品定位调整为不面向公众的自用工具，或
- 相关法规发生修订（本评估基于 2026-09 有效的法规，实施时请以官方最新发布为准）
